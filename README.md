# 米粉と鉄板 モバイルオーダー

学芸大学の鉄板料理居酒屋「米粉と鉄板」向けの、**卓の QR コードからスマホで注文 → 伝票に積み上げ → 退店時にまとめて会計** するシステムです。
Java（Spring Boot）で作られています。

```
  お客さん                    厨房                     ホール             店長
  ─────────                 ─────────                ─────────         ─────────
  卓の QR を読む             注文が届く                在席状況を見る     メニューを登録
     ↓  スマホ                 ↓  タブレット             ↓  タブレット      ↓  PC
  人数を選ぶ                 焼き始める                 伝票の金額を見る    卓と QR を発行
     ↓                        ↓                         ↓                 ↓
  メニュー → カート          提供待ち                   お会計（伝票を締める） 売上を見る
     ↓                        ↓                         ↓
  注文する ───────────→  卓へ運ぶ  ──────────→  ご退店
     ↓
  伝票に加算（追加注文もOK）
```

**1 卓 = 1 枚の伝票。** 何度注文しても同じ伝票に積み上がり、退店時にまとめて会計します。
テーブルチャージ（¥450/人）と 23 時以降の深夜料金（10%）も自動で計算します。

## 動かしてみる

### 必要なもの

| もの | バージョン | 確認コマンド |
|---|---|---|
| JDK | **21 以上** | `java -version` |
| Maven | 3.9 以上（無くても後述のスクリプトが用意します） | `mvn -v` |

JDK が入っていない場合は [Eclipse Temurin 21](https://adoptium.net/temurin/releases/?version=21) をインストールしてください（Windows なら `.msi` を選ぶのが簡単です）。

### いちばん簡単な起動方法

PowerShell でプロジェクトのフォルダを開いて：

```powershell
.\tools\run.ps1
```

Maven が入っていなければ自動でダウンロードして使います（`.tools\` 配下・`.gitignore` 済み）。

起動したらブラウザで <http://localhost:8080> を開いてください。

### Maven が入っている場合

```powershell
mvn spring-boot:run
```

### IntelliJ IDEA / VS Code で開く場合

- **IntelliJ IDEA**: `File → Open` でこのフォルダを選ぶ → 依存関係が自動で取得される → `KomekoOrderApplication` の左の ▶ を押す
- **VS Code**: 拡張機能「Extension Pack for Java」を入れてフォルダを開く → `KomekoOrderApplication.java` の `Run` を押す

### 初期アカウント

初回起動時にメニューと初期アカウントが作られます。
**パスワードはランダムに自動生成され、起動ログに 1 回だけ表示されます。**

```
============================================================
 初期アカウントを作成しました。（パスワードは自動生成しました）
   管理者   : admin / xxxxxxxxxxxxxx
   スタッフ : kitchen / xxxxxxxxxxxxxx
============================================================
```

| 用途 | ユーザー名 | 権限 |
|---|---|---|
| 管理者 | `admin` | メニュー編集・売上・スタッフ管理まで |
| 厨房スタッフ | `kitchen` | 注文の進行管理のみ |

> **この表示を見逃したら**、`data\` フォルダを消して起動し直すと作り直されます。
> パスワードを自分で決めたい場合は、起動前に環境変数を設定してください。
>
> ```powershell
> $env:INITIAL_ADMIN_PASSWORD = "好きなパスワード"
> .\tools\run.ps1
> ```
>
> 設定ファイルに直接書かないのは、**Git にコミットすると履歴に残り続ける**ためです。

### データを最初からやり直したい

`data\` フォルダを丸ごと削除して起動し直してください（H2 データベースと画像がここに入っています）。

## できること

**お客さん側**

- 卓の QR を読むだけで注文できる（アプリのインストール・会員登録は不要）
- カテゴリタブ付きのメニュー、写真、説明、価格
- **アレルゲン表示**。登録済みの商品だけ「小麦不使用」バッジを出す（未登録は「店舗へお尋ねください」）
- 味・サイズ・トッピングなどのオプション選択、金額がその場で変わる
  - 「たこ焼 8個（4種類のお味を選べます）」のような *ちょうど N 種類選ぶ* にも対応
- **いつでも「お席の伝票」でいまいくらかを確認できる**（テーブルチャージ・深夜料金込み）
- 何度でも追加注文できる
- 焼き始める前なら自分でキャンセルできる

**厨房側**

- 受付 → 調理中 → 提供待ち の 3 レーンのボード。**どの卓に運ぶか**が主役
- 新しい注文が入ると **音が鳴って自動で画面が更新**される（SSE）
- 15 分以上経過した注文は赤枠で警告
- 品切れをワンタップで切り替え、即座にお客さんの画面へ反映

**ホール側**

- 在席している卓と、それぞれの現在のご請求額を一覧
- 人数の修正（テーブルチャージが変わる）
- **お会計**（伝票を締める）。深夜料金は自動判定だがスタッフが外せる
- 誤って会計したときの取り消し

**店長側**

- 卓の登録と QR の発行・印刷（卓ごとに 1 枚）
- メニュー・カテゴリ・オプションの登録／編集（画像アップロード対応）
- 売上サマリ、商品別ランキング、直近 7 日の推移
- 混雑時に**注文受付を一時停止**できる非常ブレーキ
- 営業時間・ラストオーダー・税率・テーブルチャージ・深夜料金の設定

## 技術構成

| 分類 | 使っているもの | 選んだ理由 |
|---|---|---|
| 言語 | Java 21 | LTS で長く使える |
| フレームワーク | Spring Boot 3.3 | Web サーバ・DI・セキュリティが一式そろう |
| 画面 | Thymeleaf（サーバサイド描画） | JavaScript フレームワーク無しで完結し、学習コストが低い |
| DB | H2（ファイル） / PostgreSQL | H2 はインストール不要。本番は PostgreSQL に切り替え可能 |
| 認証 | Spring Security（フォームログイン・BCrypt） | 自作しない。認証は自作が最も危険な領域 |
| リアルタイム | SSE（Server-Sent Events） | サーバ→ブラウザの一方向で足りるため WebSocket より単純 |
| QR 生成 | ZXing core | 依存を増やさないよう PNG 化は Java 標準の ImageIO で自作 |
| CSS | 素の CSS（フレームワーク無し） | 和モダンな見た目を細部までコントロールするため |
| ビルド | Maven | 情報が多く、初学者が調べやすい |

## 店内で実際に使うときの設定

### 1. QR の飛び先を LAN の IP に変える

初期状態では `http://localhost:8080` を指しているため、**お客さんのスマホからは開けません**。
アプリを動かす PC の IP アドレスを調べて設定します。

```powershell
ipconfig    # 「IPv4 アドレス」を確認（例: 192.168.0.10）
```

`src/main/resources/application.yml` を書き換えます。

```yaml
app:
  base-url: http://192.168.0.10:8080
```

書き換えたら再起動し、`/admin/tables` で店内の席に合わせて卓を作り、`/admin/qr` で**卓ごとの QR** を印刷してテーブルに貼ってください。

> QR には `{base-url}/t/{卓ごとのランダムなトークン}` が入ります。
> 卓を作り直したり QR を再発行したりすると、それまでに貼った QR は使えなくなります。

### 1.5 お客さま用の Wi-Fi を分ける

スタッフのログインパスワードを守るため、`docs\ネットワーク設定.md` の手順で
ネットワークを分離してください。
**「ゲストSSID」をそのまま ON にすると注文が動かなくなる罠**があるので、
必ずガイドを読んでから設定を。

### 2. Windows のファイアウォールを開ける

同じ Wi-Fi のスマホから届くように、8080 番ポートの受信を許可します（管理者権限の PowerShell）。

```powershell
New-NetFirewallRule -DisplayName "Komeko Order 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

### 3. 店舗設定を自分の店に合わせる

`/admin/settings` で以下を設定します。初期値は公式サイトの記載に合わせてあります。

| 項目 | 初期値 | 意味 |
|---|---|---|
| 営業時間 | 17:30 〜 翌 2:00 | **日をまたぐ営業に対応済み** |
| ラストオーダー | 翌 1:30 | これを過ぎると自動で受付停止 |
| 消費税率 | 10% | 酒類を扱うため軽減税率の対象外 |
| テーブルチャージ | ¥450 / 人 | 伝票ごとに「単価 × 人数」で加算 |
| 深夜料金 | 23:00〜5:00 に 10% | **注文した時刻**で決まる。その時間帯に出たご注文にだけ加算（チャージは着席時刻で判定） |
| 営業日の切り替え | 5 時 | 深夜 1 時の注文は前日の営業日として集計 |
| 鉄板で同時に焼ける数 | 6 | 待ち時間の目安の計算に使用 |

> 設定を変えても、**すでに開いている伝票には反映されません**。
> 伝票は来店した時点の設定をコピーして持つためです（会計の証跡として正しい挙動です）。

### 4. 厨房・ホールの端末

- 厨房のタブレットで `/kitchen` を開く（要ログイン）
- レジ／ホールのタブレットで `/hall` を開く（要ログイン）

どちらも新しい注文が入ると自動で更新されます。

### 5. バックアップ

注文・伝票・会計データは自動でバックアップされます
（毎日 4:30／**起動時の追いつき**／アプリ終了時／手動）。
4:30 に PC が落ちていても、翌日アプリを起動した瞬間に自動で追いつくので、
特別な操作は不要です。状況は `管理画面 → バックアップ` で確認できます。

**必ずやってほしいこと**：`application.yml` の `app.backup.extra-copy-dir` に
**USB ドライブか OneDrive のフォルダ**を設定してください。
未設定だと同じディスク内へのコピーなので、ディスク故障には無力です。
復元の手順（と練習方法）は `docs\バックアップと復元.md` にあります。

### 6. ライブラリの自動更新（GitHub 連携・初回のみ 3 手順）

```powershell
winget install --id GitHub.cli   # ① インストール後、PowerShell を開き直す
gh auth login                    # ② ブラウザで GitHub にログイン
.\tools\setup-github.ps1         # ③ あとは全部このスクリプトがやる
```

以後は自動で回ります：脆弱性が見つかれば**メール通知**、
ライブラリ更新は**テスト 215 件が通ったものだけ自動で取り込み**
（Spring Boot 4 のような大型更新だけは人間の確認待ちで止まる）。
店の PC への反映は月 1 回 `.\tools\run.ps1 -Update` を実行するだけです。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 起動時に `UnsupportedClassVersionError` | JDK が 21 未満。`java -version` を確認 |
| ポート 8080 が使用中 | `application.yml` の `server.port` を 8081 などに変更 |
| POST したら 403 が返る | フォームに `th:action="@{...}"` を使っていない（CSRF トークンが入らない） |
| 画面で `LazyInitializationException` | `open-in-view: false` のため、Service の中で必要な関連を読み終える必要がある |
| スマホから QR を読んでも開けない | `app.base-url` が `localhost` のまま。上の「店内で使うときの設定」を参照 |
| 厨房画面が自動更新されない | ブラウザが SSE を切っている可能性。定期リロードにフォールバックします |
| メニューを変えたのに反映されない | 初回だけ投入され、以後はスキップされます。`data\` を消すとリセット |
| `/` を開くと「QR をお読みください」になる | 正常です。どの席か分からないと注文を受けられません |
| 会計したのに金額が合わない | キャンセルした注文は請求から外れます。伝票詳細で状態を確認してください |

## ライセンス / 注意

- 学習および自店舗での利用を想定した個人プロジェクトです。
- **アレルゲン表示は本システムが保証するものではありません。** 実際にお客さまへ案内する内容は、必ず仕入元の原材料表示を確認したうえで店舗の責任で登録・運用してください。
- 決済機能は含みません（会計は店頭）。
