## 指摘 1（major・未検証）ゲストのキャンセル遮断が status エンドポイントで迂回できる

`src/main/java/jp/komeko/order/config/SecurityConfig.java:224`

修正5（`299ddf9`）の「見学者から注文キャンセルを閉じた」が実質無効になっている。

`SecurityConfig.java:224-226` は `POST /kitchen/orders/*/cancel` だけを ROLE_GUEST から遮断しているが、
`POST /kitchen/orders/{id}/status` は 235-237 行の `/kitchen/**` STAFF ルールに落ちてゲストに許可されたまま。
厨房ボードの進行フォーム（CSRF トークン付き）の hidden input `status` を DevTools で `CANCELED` に書き換えるだけで、
任意の注文をキャンセルできる。

`OrderService.changeStatus`（`OrderService.java:310-326`）は `next==CANCELED` を完全なキャンセル経路として扱い、
`requireBillStillOpenForCancel` → 伝票再計算 → `restoreStockOf` まで実行するため、結果は `/cancel` と同一。
`OrderStatus.java:78-80` では RECEIVED/COOKING/READY すべての `allowedNext` に CANCELED が含まれる。

つまり「見学用の卓の伝票から品が消え、次の見学者の `/demo` が壊れた状態から始まる」という、
この修正が防ごうとした事態がそのまま起きる。

- **prod への影響なし**（ゲストが存在しないため）。デモ環境のみ。
- ゲストの `status=CANCELED` を拒否するコードはコントローラ・サービス・SecurityConfig のどこにも無い。
- 既存テストは `status=COOKING` しか検証していない（`GuestLoginTest`）。

## 確認して問題なしと判断された点（再確認不要）

- **ROLE_GUEST の永続性**: `/login/guest` の認証トークンはセッションに保存され、権限が落ちる経路は無い。remember-me 未設定。
- **SecurityConfig のルール評価順**: ゲスト拒否 2 ルール（221-226 行）は汎用 `/hall/**`・`/kitchen/**` ルール（235-237 行）より先に登録され first-match で有効。実スタッフは従来どおり通る。
- **パターンマッチ**: `/kitchen/orders/*/cancel` の `*` は 1 セグメントに一致し実パスに正しく合う。
- **prod（guestLoginEnabled=false）**: 式ルール不在でも `hasAnyRole('STAFF','ADMIN')` で従来どおり。`ProductionSafetyGuard` が prod×guest-login=true の起動自体を止めるため安全。
- **ProductionSafetyGuard の実行タイミング**: eager singleton のコンストラクタで例外を投げ refresh を失敗させるので、`DemoDataSeeder`（ApplicationRunner）や `BackupService`（ApplicationReadyEvent）より必ず先に止まる。
- **sec:authorize の動作**: `thymeleaf-extras-springsecurity6` は `pom.xml:74` にあり、`xmlns:sec` 宣言の有無は処理に影響しない。
- **kitchen/board.html**: 進行ボタンとキャンセルは別 div なので空箱は出ない。
- **ゲストのフォームログイン抜け道なし**: guest のパスワードは `{noop}`+ランダム UUID。
- **settings.html の新警告文**: 判定は注文ごとの `createdAt`、テーブルチャージのみ `openedAt`、終了時刻は排他的（`ShopSetting.java:464-465`）で記述は正確。割増率 0 で全額消えるのも正確。
- **demo-preparing.html の `${shop.shopName}`**: `orElseGet(ShopSetting::new)` で既定値を返すため起動直後でも NPE しない。
- **ポートフォリオ.md の新導線**: `/demo`・`/demo/staff` は両方 permitAll で記述と一致。
- **ホール「本日の会計済み」一覧**: GET リンクのみでゲストに残る書き込み経路なし。
