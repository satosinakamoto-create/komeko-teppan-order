# 店舗導入のフローチャート（矛盾を探すための地図）

QR コード注文を「米粉と鉄板」に実際に入れる前提で、店の仕事の流れを図にしたもの。
商品とレシピの分断（2026-09-14 に発覚）のような**画面どうしの矛盾・順序の罠**を、
導入前に洗い出すのが目的。⚠ が付いている箱がその候補。

凡例：🟥 矛盾（直す対象）／🟨 順序の罠（知らないと詰まる）／🟦 運用でカバー（システムは強制しない）／⬜ 決めて捨てたこと

---

## 1. 導入前の準備（一度だけ）

```mermaid
flowchart TD
    A["ネットワーク設定<br>店内 LAN・スタッフ端末の IP 制限"] --> B{"app.base-url は<br>店の実 IP か？"}
    B -- いいえ --> B2["🟨 修正必須<br>ここを直す前に QR を印刷すると<br>印刷した QR が全部ゴミになる"]
    B2 --> B
    B -- はい --> C["店舗設定<br>営業時間・チャージ・深夜料金"]
    C --> C2["⬜ 曜日別の営業時間は無い<br>土日 16:00 開店は毎週手で変えるか、妥協"]
    C2 --> D["スタッフ登録・初期パスワード変更"]
    D --> E["卓の登録（名前は番号札と同じに）"]
    E --> F["QR 印刷 → 各卓に設置"]
    F --> G["スマホ実機で全卓の QR を読んでテスト"]
    G --> H["カテゴリ登録"]
    H --> H2["🟨 カテゴリが先<br>商品は所属カテゴリ必須なので<br>カテゴリ 0 件だと商品を 1 品も登録できない"]
    H2 --> I["食材の登録（在庫を使うなら）"]
    I --> J["商品の登録"]
    J --> K["レシピの登録"]
    K --> K2["🟥 商品とレシピが別画面で導線なし<br>→ 2026-09-14 に設計済み：一覧に原価列・<br>追加直後の案内・サイドバー移動（実装待ち）"]
    K2 --> L["掲載 ON（品出し）"]
    L --> M["自動バックアップの確認"]
    M --> N["営業リハーサル<br>注文→厨房→提供→会計→バッシング を一周"]
```

- 🟨 **base-url → QR 印刷の順序**は最重要。逆にすると貼り直し。現状 dev 設定は `192.168.1.4` のままで実 IP と不一致（既知）。
- 🟨 **サイドバーの並びと作業順序が逆**な箇所が残る：初期設定は「カテゴリ → 商品」の順だが、画面の並びは商品が上。初回だけの話なので導線までは作らない（リハーサル手順書でカバー）。

## 2. 新メニューを出す（繰り返しの仕事）

```mermaid
flowchart TD
    A["新メニューを決める"] --> B{"新しい食材を使う？"}
    B -- はい --> C["食材・在庫で食材を登録"]
    C --> C2["🟨 レシピ編集の途中で食材が無いと気づくと<br>画面を往復することになる（食材が先）"]
    B -- いいえ --> D
    C2 --> D["商品を登録（名前・カテゴリ・税込価格・写真）"]
    D --> E{"時価の品？"}
    E -- はい --> F["価格 0 円＋品切れで登録<br>（お客さまからは注文できない状態）"]
    E -- いいえ --> G["レシピを登録（食材と分量）"]
    G --> G2["🟥 レシピ未登録でも掲載できてしまう<br>売れても在庫が減らず「あと◯営業日」が甘く出る<br>→ 一覧の赤い「未登録」で発見できるようにする（設計済み）"]
    F --> H["掲載 ON"]
    G2 --> H
    H --> I["お客さまのメニューに載る"]
```

- ✅ 確認済み：**価格 0 円のままの販売再開は画面が断る**（2026-09-07 のガード）。0 円で注文できる品は構造的にできない。

## 3. 毎日の開店前

```mermaid
flowchart TD
    A["開店前"] --> B{"時価の品はある？"}
    B -- はい --> C["当日価格を入れて販売再開<br>（サーロイン ¥3,800 など）"]
    C --> C2["🟦 入れ忘れると今日はその品が売れないだけ<br>0 円で売れる事故にはならない（ガード済み）"]
    B -- いいえ --> D
    C2 --> D["昨日の品切れを戻す・数量限定の残数を入れる"]
    D --> D2["🟦 開店前チェックを促す画面は無い<br>ダッシュボードは営業中の数字が主<br>→ 紙のチェックリストでカバー"]
    D2 --> E["受付中の確認（上の帯が緑）→ 営業開始"]
```

## 4. 来店 → 注文 → 提供（営業中）

```mermaid
flowchart TD
    subgraph 入店["入店（2 つの入口がある）"]
      A1["ホールが「＋新規お客様」<br>人数と卓を選んでご案内"] --> S["伝票 OPEN"]
      A2["お客さまが卓の QR を読む"] --> A3{"その卓の伝票は開いている？"}
      A3 -- いいえ --> A4["人数を聞いて伝票 OPEN<br>（お客さま自身で開ける）"]
      A3 -- はい --> M1
      A4 --> S
    end
    S --> M1["お客さまのスマホにメニュー"]
    M1 --> O1["カートに入れて注文確定"]
    O1 --> O2{"確定時の検査"}
    O2 -- 品切れの品だけ --> O3["その品だけ落として残りは通す"]
    O2 -- 金額や中身が変わった --> O4["止めて確認してもらう"]
    O2 -- 問題なし --> K1
    O3 --> K1["厨房ボード（受付）"]
    K1 --> K2["調理中（焼きはじめ）"] --> K3["提供待ち"] --> K4["提供済み"]
    K4 --> R["追加注文は同じ伝票に積み上がる"]
    R --> M1
    O1 --> N1["🟦 深夜料金は注文時刻で決まる（23:00〜）<br>打ち直しの救済（明細ごとの免除）は人の操作<br>→ ホール全員が知らないと使われない：教育でカバー"]
```

- ✅ 整合確認済み：入口が 2 つあっても人数の**二重入力にはならない**（既に開いた伝票では人数画面が出ない。開いた伝票の人数を客側から減らすこともできない）。
- ✅ 残数 0 の品はスタッフ注文でも必ず断る（売り越し防止）。

## 5. 会計 → バッシング → 次の組

```mermaid
flowchart TD
    A["お客さまが席で「お会計」<br>またはホールが操作"] --> B["お会計待ち列へ（赤）"]
    B --> C["レジで現金 or キャッシュレス端末<br>（アプリ内決済はしない）"]
    C --> D["会計を確定（伝票 CLOSED・売上確定）"]
    D --> E["卓はバッシング列へ（◯名席 表示）"]
    E --> F{"待っている組は何名？"}
    F --> G["人数に合う席から片付ける<br>2名待ち → 4名席より 2名席を先に"]
    G --> H["バッシング完了 → 空席"]
    H --> I["空席 ◯卓（新規お客様ボタンの脇）が増える"]
    I --> J["次の組をご案内"]
    D --> X["間違えて会計した？<br>→ 本日の会計済みから戻せる"]
    A2["停電・スマホの紐付きが切れた"] --> A3["もう一度 QR を読めば復帰<br>（会計時に卓と注文が分かれば良い、と決めた仕様）"]
```

## 6. 閉店後・月次

```mermaid
flowchart TD
    A["閉店"] --> B["売上・注文履歴を確認"]
    B --> C["仕入れのレシートを登録（写真から）"]
    C --> C2["🟦 レシート登録を溜めると在庫の理論値がずれていく<br>→ 週の頻度を決める（運用）"]
    C2 --> D["食材・在庫の残りを確認<br>発注の判断（あと◯営業日）"]
    D --> D2["🟨 レシピ未登録の品が多いほど<br>「あと◯営業日」は長め（甘め）に出る<br>→ 2 の赤い「未登録」を潰すほど精度が上がる"]
    D2 --> E["バックアップが取れているか確認"]
    E --> F["月次：税理士の画面<br>今月のまとめ・消費税・証憑・仕訳の書き出し"]
```

## 7. 見つかっている矛盾・穴の一覧

| # | 種類 | 内容 | 状態 |
|---|---|---|---|
| 1 | 🟥 矛盾 | 商品の登録とレシピの登録が別画面で、導線がゼロ。登録漏れが起きる前提の作りだった | **設計済み**（原価列・追加直後の案内・サイドバー移動）。実装待ち |
| 2 | 🟥 矛盾 | レシピ未登録でも掲載でき、在庫と原価が黙って狂う | #1 の赤い「未登録」で見えるようにする |
| 3 | 🟨 順序の罠 | base-url を直す前に QR を印刷すると全部無駄になる。現状 dev は実 IP と不一致 | **導入前の必須手順**として 1 の図に固定 |
| 4 | 🟨 順序の罠 | カテゴリ 0 件だと商品が登録できない／食材が無いとレシピで手が止まる | リハーサル手順書でカバー（初回だけ） |
| 5 | 🟦 運用 | 時価の品の当日価格は毎営業日の人手作業。忘れてもその品が売れないだけ（0 円販売はガード済み） | 開店前チェックリストへ |
| 6 | 🟦 運用 | 深夜料金の打ち直し救済（明細ごとの免除）は知らないと使われない | スタッフ教育へ |
| 7 | 🟦 運用 | 営業中の価格変更は「販売中止 → 変更 → 再開」の手順をシステムは強制しない | 手順書へ（仕様.md 4.6.1） |
| 8 | ⬜ 決めた | 曜日別の営業時間なし（土日 16:00 は手動） | 導入後に痛ければ再検討 |
| 9 | ⬜ 決めた | 停電時の紐付き切れは QR 再読みで復帰 | 2026-09 に店主と合意済み |
| 10 | ❓ 要確認 | レシピ編集の画面から食材の新規登録に飛べるか（飛べないなら 4 の往復が毎回起きる） | 次の実装のときに確認 |
| 11 | ❓ 要確認 | 棚卸（実在庫と理論在庫の突き合わせ）の置き場所。手修正の入口がどこか | docs\現場の話_発注と棚卸_2026-09-05.md と突き合わせる |
