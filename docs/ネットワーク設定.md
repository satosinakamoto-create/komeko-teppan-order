# ネットワーク設定ガイド — お客さまとスタッフの通信を分ける

最終更新: 2026-08-17

このシステムはアプリ側の対策（認証・CSRF・改ざん検証など）は済んでいますが、
**通信が HTTP（暗号化なし）** のため、スタッフのログインパスワードが
店内 Wi-Fi を平文で流れます。同じネットワークにいる人からは技術的に盗聴できます。

その対策は**コードではなくルーターの設定**で行います。このガイドの通りにやれば
費用ゼロ・コード変更ゼロで塞がります。

---

## ⚠️ 最初に知るべき罠：「ゲストSSID」をそのまま ON にすると注文が止まる

多くのルーターの「ゲスト機能」は **LAN からの完全隔離** が本質です。
ゲストに繋いだ端末は、インターネットには出られますが**店内の機器には一切届きません**。

このシステムはサーバが店内の PC にあるので、
お客さまのスマホがゲスト側にいると **QR を読んでもメニューが開かなくなります**。

> クラウド型 POS（Air レジ等）にこの問題が無いのは、サーバがインターネット上に
> あるからです。自前サーバ構成では「お客さまも店内ネットワークに入る」のが前提になります。

---

## 推奨構成

```
インターネット ─── ルーター
                    ├─ 有線LANケーブル : サーバPC（注文システム）★必ず有線
                    ├─ SSID1（スタッフ用）: 厨房・ホールのタブレット
                    └─ SSID2（お客さま用）: プライバシーセパレーター ON
```

3 つのポイント：

1. **サーバ PC は必ず有線接続にする。**
   安定・速度のためでもありますが、後述のセパレーターの仕組み上、
   有線にしておくと「お客さまからサーバには届くが、無線端末同士は遮断」が成立します。

2. **お客さま用は「ゲストモード」ではなく「2 つ目の SSID（マルチ SSID）」を使い、
   プライバシーセパレーター（ネットワーク分離）を ON にする。**
   - プライバシーセパレーター＝「無線クライアント同士の通信を遮断する」機能。
     多くの機種で、無線→**有線**への通信は通します。
   - つまり：お客さま → サーバ PC（有線）は届く ✓
     お客さま → 別のお客さまのスマホ ✗
     お客さま → スタッフのタブレット（無線）✗
   - これが今回やりたいことのすべてです。

3. **スタッフ用 SSID のパスワードは店内に掲示しない。**
   お客さま用 SSID のパスワードは卓の POP に書いて構いません（注文に必要なので）。

### 機種ごとの機能名（設定画面で探す言葉）

| メーカー | 使う機能 | 注意 |
|---|---|---|
| Buffalo | 「マルチSSID」＋「プライバシーセパレーター」 | 「ゲストポート」は LAN 遮断型のことが多く**不向き** |
| NEC Aterm | 「セカンダリSSID」＋「ネットワーク分離機能」 | セカンダリ側だけ分離を ON |
| TP-Link | 「ゲストネットワーク」 | 「ローカルネットワークへのアクセスを許可」に**チェックを入れる**＋「ゲスト同士の通信を許可」は外す |
| その他 | 「SSID2」「AP隔離」「クライアント分離」等 | 名前は違っても仕組みは同じ |

> 機種によって挙動に差があります。**設定したら必ず下のチェックリストで確認**してください。
> どうしても「分離」と「サーバへの到達」を両立できない機種の場合は、
> 全員同じ SSID のままでも「プライバシーセパレーターだけ ON」にする価値があります
> （サーバが有線なら注文は動き、無線端末同士の盗聴は塞がります）。

## あわせてやること：サーバ PC の IP を固定する

QR コードには `http://192.168.x.x:8080/t/...` のように **PC の IP アドレス**が入っています。
DHCP のままだと再起動で IP が変わり、**印刷済みの QR が全部無効になります**。

ルーターの設定画面で「**DHCP 固定割当（IP アドレス予約）**」を探し、
サーバ PC の MAC アドレスにいまの IP を割り当ててください。
（PC 側で固定するより、ルーター側で予約するほうが事故が少ないです）

---

## 設定後の確認チェックリスト

すべて ✓ になったら完了です。

- [ ] **お客さま用 SSID** に繋いだスマホで卓の QR を読む → メニューが開く
- [ ] 同じスマホから注文 → 厨房画面に届く
- [ ] 同じスマホのブラウザでスタッフ端末の IP を開いてみる → **届かない（タイムアウト）**
- [ ] **スタッフ用 SSID** のタブレットで `/kitchen` `/hall` が開く
- [ ] サーバ PC を再起動しても IP が変わらない（QR がそのまま使える）
- [ ] お客さま用 SSID の掲示に、スタッフ用のパスワードが書かれていない

## それでも残るもの（正直な整理）

- お客さま用 SSID に入った人は、**サーバの注文ページには届きます**（届かないと注文できないので当然）。
  サーバ側はもともと「客に開いていい URL」しか許可していないため（SecurityConfig）、
  ここは追加のリスクにはなりません。
- スタッフ端末が**有線**の場合、セパレーターの保護対象外になる機種があります。
  上のチェックリスト 3 番で必ず確認してください。
- 将来インターネットに公開する（店外から注文できるようにする）場合は、
  この構成では足りません。HTTPS・レート制限・監視が必須になります。
