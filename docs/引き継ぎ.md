## 🚨 実店舗で使う前に必ずやること

**この 5 つを片付けないと営業に使えません。**

### 1. 価格の税抜／税込を確定する

公式サイトのドリンクページに「**表示価格は税抜きです**」と明記されています。
料理ページには表記がありません。
このシステムは**価格を税込で持つ**設計なので、税抜のまま登録すると請求額が不足します。

- どちらなのかを店舗に確認する
- 税抜なら、管理画面 → 商品 で税込価格に直す（または一括で直すスクリプトを書く）

### 2. アレルゲンを登録する

**現在、全商品でアレルゲンが未登録です。意図的にそうしています。**
食物アレルギーは命に関わるため、こちらで推測して入れることはしませんでした。

未登録の商品には「アレルギーは店舗へお尋ねください」と表示されます。
原材料の仕入元表示を確認したうえで、管理画面 → 商品 から登録してください。
登録した商品だけ「小麦不使用」バッジが出るようになります。

### 3. 卓を実際の店内配置に合わせる

初期データは「カウンター1〜6／テーブル1〜4」のひな形です。
管理画面 → 卓 で実際の席に作り直し、管理画面 → QRコード から印刷してテーブルに貼ってください。

### 4. ルーターでお客さま用の SSID を分ける

スタッフのログインパスワードが店内 Wi-Fi を平文で流れるため、
`docs\ネットワーク設定.md` の手順でネットワークを分離する。
**注意: 普通に「ゲストSSID」を ON にするとお客さまがサーバに届かず注文が止まる。**
必ずガイドの構成（サーバ有線＋マルチSSID＋セパレーター）とチェックリストで。
あわせてサーバ PC の IP をルーター側で固定予約する（QR が無効にならないように）。

### 5. QR の飛び先を LAN の IP に変える ✅ 済（2026-08-18）

`application.yml` の `app.base-url` が `http://localhost:8080` のままだと、
**お客さんのスマホからは開けません。**

```powershell
ipconfig    # IPv4 アドレスを確認（例 192.168.0.10）
```

```yaml
app:
  base-url: http://192.168.0.10:8080
```

現在は `http://192.168.1.4:8080` に設定済みで、
**実機（Android / Chrome）で卓 QR → 注文画面の表示まで確認済み**です。
ただしこの IP は DHCP なので、ルーターで固定予約するまでは変わりえます（上記 4 参照）。

> スマホから開けないときは `docs\ネットワーク設定.md` の
> 「スマホから開けないときの調べ方」を上から順に。
> 2026-08-18 の実話として、**Windows ファイアウォールに残っていた
> OpenJDK への「拒否」ルール**が原因でした（拒否は許可より強いので、
> 8080 の許可ルールを作っても効かない。ping は通るのに 8080 だけ落ちる）。
> アプリ初回起動時のセキュリティ警告で「キャンセル」を押すと自動生成されます。

## 仕様として「そうしている」こと（バグではない）

問い合わせが来がちな点をまとめておきます。

- **`/` を直接開くと「QR をお読みください」になる。**
  どの席か分からないと注文を受けられないため。正常な挙動です。
- **店舗設定を変えても、すでに開いている伝票の金額は変わらない。**
  伝票は来店時点の設定をコピーして持っています。会計の証跡として正しい挙動です。
- **キャンセルした注文は請求から消える。** 伝票の金額も自動で減ります。
- **注文番号が飛ぶことがある。** 番号を使い回して別のお客さんに同じ番号を渡すより安全なためです。
- **深夜料金は 23:00〜翌 5:00 に適用される。** 「23 時以降」を素直に書くと深夜 1 時が漏れるためです。
  範囲は管理画面で自由に変えられます。ホール画面でスタッフが外すこともできます。
- **営業時間外は人数選択のボタンが押せない。** どの席か以前に、そもそも受け付けていないためです。
  動作確認のときは下の「24 時間受付」を使ってください。
- **年齢確認はできない。** スマホからは確認しようがないので、提供時に店頭で確認する運用です。

## 営業時間まわりの操作（2026-08-18 追加）

### 動作確認したいのに「本日の営業は 17:30 からです」で止まるとき

管理画面 → 店舗設定 → **「24 時間受付にする」を ON にして保存**。
時刻による自動停止をしなくなるので、何時でも注文フローを通せます。
営業時間の値は消えないので、**OFF に戻せばそのまま元に戻ります**
（時刻を書き換えて戻し忘れる、という事故が起きません）。

急な営業時間の変更（今夜だけ朝までやる等）にも同じ手が使えます。

> **「今すぐ止める」とは別のスイッチです。**
> 24 時間受付にしていても、受付停止の非常ブレーキはいつでも効きます。

### 時刻の選択肢

開店・ラストオーダー・閉店・深夜料金の開始／終了は、
**すべて 0:00〜23:59 の好きな値**を入れられます（決まった選択肢はありません）。
`17:30 開店 → 翌 1:30 ラストオーダー` のように**日をまたぐ指定もそのまま**書けます。
開店時刻よりラストオーダーが小さければ日跨ぎと解釈されます。

深夜料金も同じで、`23:00 → 5:00` と入れれば深夜 1 時の会計にもかかります。

## パスワードを完全に忘れたときの復旧手順

「パスワードを忘れました」リンクはこのシステムにはありません（メールを持たないため）。
代わりに、**サーバ PC の前に座れる人＝店の人**という前提でこう復旧します。

1. アプリを停止する（Ctrl+C）
2. スタッフのアカウントを全部消す（DB ファイルから直接）

   ```powershell
   cd C:\Users\zaki\projects\komeko-teppan-order
   # H2 のシェルで SQL を 1 行実行（h2 の jar は Maven が取得済みのものを使う）
   $h2 = Get-ChildItem "$env:USERPROFILE\.m2\repository\com\h2database\h2" -Recurse -Filter "h2-*.jar" | Select-Object -First 1
   java -cp $h2.FullName org.h2.tools.Shell -url "jdbc:h2:file:./data/komeko" -user sa -password "" -sql "DELETE FROM staff_user"
   ```

3. 新しいパスワードを決めて起動する

   ```powershell
   $env:INITIAL_ADMIN_PASSWORD = "新しいパスワード"
   .\tools\run.ps1
   ```

   スタッフが 0 人だと、初期投入（DataSeeder）が admin / kitchen を作り直します。
   注文・伝票・メニューのデータは一切消えません（消すのは staff_user だけ）。

4. ログインできたら `$env:INITIAL_ADMIN_PASSWORD` の設定は消してよい
   （その PowerShell を閉じれば自動で消えます）

## 詰まったときの調べ方

| 症状 | 見るところ |
|---|---|
| 起動しない（PowerShell の構文エラー） | `.ps1` が BOM 無しになっていないか（CLAUDE.md 参照） |
| POST が 403 | フォームが `th:action="@{...}"` になっているか（CSRF） |
| 画面が真っ白／500 | ログの `Exception evaluating SpringEL expression` を探す |
| `LazyInitializationException` | Service の中で関連を読み終えているか（`hydrate`） |
| 会計金額が合わない | 伝票詳細で各注文の状態を確認。キャンセルは請求から外れる |
| メニューを変えたのに反映されない | 初回だけ投入。`data\` を消すとリセット |
