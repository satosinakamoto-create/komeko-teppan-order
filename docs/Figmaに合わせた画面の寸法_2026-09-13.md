# Figma に合わせた画面の寸法（2026-09-13）

Figma のデータを機械採寸して、コードとの差をぜんぶ埋めた記録。
「フィグマデータ通りに実装して」で始まった作業。

## どうやって差を出したか

1. Figma の `01 画面（店舗・税理士）` ページを丸ごと XML で取り出し、
   画面ごとに「本文の子」を y 座標つきで並べる
2. 同じ 16 画面をブラウザで 1024 / 1432 / 1920px で描き、同じ値を採寸する
3. 突き合わせる

目で見比べない。数字どうしを引き算する。
この方法にしてから、1 回の作業で 12 画面ぶんの差が一度に見つかるようになった。

## 直したもの

### 1. 本文の上下余白（先にやった分）

| | Figma | 直す前 |
|---|---|---|
| 食材・在庫／レシピ・原価表／バックアップ | 64px | 64px |
| 上記以外の 13 画面 | 32px | 64px |

基準の取り方が逆だった。「基準 64、4 画面だけ 32 に落とす」→
「基準 32、3 画面だけ 64 に上げる」に反転。10 画面が一度に合った。

### 2. 見出しの帯

  大見出し 32px Bold  #1c1c1c
  補足     14px       #828282
  ボタン   高さ 48px  角丸 4px

- **卓・QRコード・注文履歴・レシピ・原価表** の 4 画面が `.section-title`

  ページの見出しより 40px 外側から始まっていた

### 3. 本文の縦オートレイアウト

Figma の本文はぜんぶ縦のオートレイアウト。コードは要素ごとの margin だった。
1432px で採ると、1 画面の中に **0・4・11・15・16・24・31・32・40・57px** が
混ざっていた。48px でそろっていたのは 4 画面だけ。

`app.css` 41 節で flex ＋ gap に一本化した。

| | ブロックの間 |
|---|---|
| 机で読む 12 画面 | 48px |
| 立って使う 3 画面（厨房・ホール・品切れ） | 24px |
| 売上 | 20px |
| iPad（1380px 以下） | 一段詰めて 32px（例外の 4 画面は据え置き） |

## 踏んだ罠

### ★ 立って使う 3 画面は 01 ページを見ない

01 ページの `03 ホール・会計` と `04 品切れ・残数` は共通部品で描かれているが、
この 3 枚は 2026-09-12 に **現01 552:6627 / 現02 542:3705 / 現03 439:2496** として
作り直してあり、そちらが正。

- 見出しの帯 … 現02 は 20/40（帯 88px）。01 ページの 16/40（77px）ではない
- ブロックの間 … 現02・現03 とも 24px。01 ページの 48px ではない

実際に 01 ページだけ見てホールの帯を 16px に下げ、戻した。
48px を採ると 1 画面に入る伝票が減る。
「2 つしか見えなくて視認性が悪い」と言われて詰めた画面なので、
ここを広げるのは前の判断を黙って戻すことになる。

### ★ flex にすると margin が相殺されない

gap を入れただけだと、子に残った margin がそのまま足し算される（48 + 24 = 72）。
`> * { margin-block: 0 }` が要る。

そのうえで、**わざと残す margin もある**。
ホールの盤面（`.theme-desk .hallboard .board`、詳細度 0,3,0）は
現02 に 8px の白い矩形が挟んであるぶんを margin で出しているので、
gap 24 ＋ margin 32 ＝ 56px になるよう margin だけ 56→32 に直した。

### ★ gap は高さ 0 の子にも入る

お知らせの枠（`fragments/common :: flash`）は、出すものが無くても
`<div class="stack-sm">` だけは必ず出る。放っておくと全画面の先頭に 48px の空白ができた。

`:empty` は「空白だけの中身」の扱いがブラウザで割れるので、
`:not(:has(*))`（要素の子がひとつも無い）で見ている。

### ★ 効かない 1 行を作らないこと

41 節のセレクタは `.theme-desk .staff-main > main`（詳細度 0,2,1）。
40 節（iPad の一段下げ）にあった `.dashpage { gap: 32px }`（0,1,0）は、
41 節が後ろにあるぶん常に負ける。読めるのに効かない 1 行になるので、
ブロック間の一段下げは 41 節へ移した。

## 決めていないこと（店主に聞く）

### 1. 大見出しの行間 36px か 44.8px か

- **Render 実測** … 32px / 行間 36px
- **Figma の部品** … 32px / 行間 1.4（＝44.8px）

どちらも指示から入れた値。いまは Render の 36px。
そのため、ボタンの無い見出し帯は **68px**（Figma は 77px）。
ボタンのある帯は 48px のボタンが効くので 80px で一致している。

変えるなら `app.css` の `.page-head__title` の 1 行だけ。
`RenderAlignedTypeTest` も直す。

### 2. 卓・QRコードの「追加」ボタン

Figma の `10 卓` `11 QRコード` は<b>一覧だけの画面</b>で、本文に追加フォームが無い。
代わりに見出し帯に「卓を追加」「まとめて印刷」のボタンが立っている。

いまのコードは 1 枚の画面に一覧と追加フォームが同居しているので、
ボタンを足すにはカテゴリ・スタッフと同じく画面を 2 枚に割ることになる。
これは寸法ではなく画面構成の話なので、勝手にやらずに置いてある。

### 3. 税理士の 5 枚

`layout/accountant.html` は `<main class="staff-main">` で、本文がこの入れ子になっていない。
Figma では 48px でそろっているので同じ扱いにできるが、
一度に広げると壊れたときの切り分けができなくなるので分けた。

## まだ残っている既知の不具合

- 商品の表が 1024px で横に 255px はみ出す（列幅の合計が 1120px 固定のため）。
  承認済みのモックも横スクロールする形なので、そのままにしてある
- QRコードの画面が 1024px で 34px はみ出す
- 商品の画面が 768px 未満ではみ出す（タブ 5 個 × 136px）
